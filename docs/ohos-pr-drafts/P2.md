### What does this PR do?

Part of the focused OHOS series tracked in #47951.

Adds the test-harness pieces the OHOS runner needs: `isOHOS`/`isOhos` detection (`BUN_OHOS=1`, with a musl-loader probe for a device run started without it), a pinned `TMPDIR` for children (the OHOS sandbox denies rename() on `/tmp`), and `--expose-internals` for child `bun` processes so fixtures that import `bun:internal-for-testing` work on release builds too. No product code changes.

This is the prerequisite for the `isOhos` test gates and the OHOS device lane; it does not change Linux/macOS/Windows behavior.

### How did you verify your code works?

- Existing suites on Linux/macOS/Windows are unchanged (the new branches only run when `BUN_OHOS=1` or the OHOS musl loader is present).
- On the OHOS device, the harness resolves `isOhos` both with `BUN_OHOS=1` and without it (loader probe), and child processes inherit the app-private `TMPDIR`.
- The fork's full-suite runner uses this harness; the device lane (P19) will exercise it in CI.
