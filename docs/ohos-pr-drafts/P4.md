### What does this PR do?

Supersedes #30315. Part of the focused OHOS series tracked in #47951.

`os.cpus()` matched `/proc/cpuinfo` with the literal prefixes `processor\t: ` and `model name\t: `. ARM kernels often use different whitespace and report the SoC only in `Hardware`, so those cores got `model: "unknown"`.

Parse each line at the first `:` and trim both sides. `model name` keeps precedence on every core; `Hardware` fills the cores that have no `model name`; a core with neither stays `"unknown"`. The parser keeps each `/proc/cpuinfo` `processor` ID, and `cpus_impl_linux` looks models up by that ID, so an offline CPU that leaves a gap in `/proc/stat` does not shift the models. The cpufreq path uses the same CPU ID. x86 behavior is unchanged.

### How did you verify your code works?

- Eight unit tests in `src/runtime/node/node_os.rs`: x86 model name, ARM `Hardware` fallback, model-name precedence, per-core mix, missing model, a processor beyond the online count, sparse IDs (`cpu0`/`cpu2` and `cpu0`/`cpu2`/`cpu3`), and a processor ID beyond the timing entries.
- A standalone run of the same parser cases on the OHOS host passed 8/8; the in-tree tests use `bun_core::strings` and run with the Rust suite in CI.
- `bun test test/internal/source-lints/byte-search.test.ts` passes (3/3) after using `bun_core::strings::split` and `index_of_char_usize`.
- No JS-visible API change; `os.cpus()` keeps the same shape.
